# Local commands

Run these commands from the workbench root. Python 3.11+, Git, .NET SDK
**11.0.100**, a .NET 10 runtime, and **JDK 21** are the tested prerequisites.
`global.json` selects that installed SDK exactly; it does not download one.
Host projects target `net10.0`; the package tasks require modern .NET 11
MSBuild. The source's separate .NET 12 product-build pin remains unchanged.

Set `JAVA_HOME` to your JDK 21 installation. For Android compilation also set
`ANDROID_HOME` (or `ANDROID_SDK_ROOT`) to an existing Android SDK and use an
installed .NET 11 Android workload. The fresh sample used Android workload
**37.2.31** on macOS ARM64. Other workload/OS combinations need their own run.

## Rebuild the workbench

```sh
python3 eng/workbench.py doctor
python3 eng/workbench.py verify-preservation
python3 eng/workbench.py bootstrap
python3 eng/workbench.py build
python3 eng/workbench.py test
python3 eng/workbench.py pack
python3 eng/workbench.py generate
```

| Command | What it does |
| --- | --- |
| `doctor` | Reports Python, Git, installed SDKs, selected SDK and Java; installs nothing |
| `verify-preservation` | Checks original source/text hashes and agreement between historical asset indexes |
| `verify-snapshot` | Checks the patch, all additions and exact source-payload inventory |
| `bootstrap` | Fetches the exact upstream commit, applies the patch, copies additions/modes and verifies all 277 source outputs |
| `build` | Builds generator, class-parse, grouped-bindings and binding-compatibility; tests/installs the JVM descriptor |
| `test` | Runs generator, package-task, corpus Python and workbench bootstrap regressions |
| `pack` | Restores/builds parser and generator, builds the descriptor, packs/inspects the compiler and writes matching source provenance |
| `inspect` | Inspects the already-built local compiler package and writes its content list |
| `generate` | Compiles native Java, generates a semantic Android binding and compiles its C# consumer |
| `verify-package --work-dir ...` | Runs the fuller no-device package fixture against the installed workload |
| `tool NAME ...` | Discovers a built host tool's actual `TargetPath` through MSBuild, then invokes it |

`build`, `test`, and compiler `pack` do **not** run `make prepare`, install a
workload, or use `dotnet-local.sh`. They do restore pinned build dependencies
from the source's public feeds. Gradle uses the source's pinned wrapper and
dependency versions. Normal user NuGet/Gradle caches are allowed; no previous
session's cache is needed.

Options selecting the source and dotnet host precede the command:

```sh
python3 eng/workbench.py --source .artifacts/another-source bootstrap
python3 eng/workbench.py --source .artifacts/another-source build
python3 eng/workbench.py --dotnet /path/to/installed/dotnet test
python3 eng/workbench.py generate --jdk "$JAVA_HOME" --android-sdk "$ANDROID_HOME"
```

Use an ignored `.artifacts/` directory, or a location outside this repository,
for an alternate source tree. Bootstrap refuses to overwrite a nonempty
unrecognized directory. If fetching or applying fails, keep the diagnostic
output and retry with a new empty source path. Repeating bootstrap on its own
completed checkout verifies it without overwriting source.

Packing requires the preserved source to be unmodified, including the git
changed/untracked inventory, so the resulting provenance describes the code
actually used. Research edits can still be built and tested separately; use an
explicitly reviewed new snapshot before publishing them with source hashes.

## Outputs

Everything generated by the wrapper is under ignored `.artifacts/`:

| Path | Contents |
| --- | --- |
| `source/` | Materialized upstream and the experiment, including ordinary upstream `bin`/`obj` outputs |
| `feed/` | Rebuilt `0.1.0-preview.workbench.1` compiler nupkg and its matching source/package provenance |
| `package-contents.txt` | Inspected compiler package entries |
| `hello/` | Disposable copy of the hello source, compiled JAR, generated C#, binding DLL and consumer DLL |
| `sample-packages/`, `fixture-packages/` | NuGet caches keyed by nupkg hash; restored compiler bytes must match the feed |
| `tmp/` | Child-process temporary files |

The hello runner refreshes the disposable sample copy. Edit `samples/hello/`,
not `.artifacts/hello/`. Its no-device result proves compilation, not JNI
execution or compatibility of unrelated native graphs.

## Existing package integration fixture

After `pack`, this no-device command exercises the fuller preserved fixture.
Choose a **new** work directory each time:

```sh
python3 eng/workbench.py verify-package \
  --work-dir .artifacts/package-check \
  --jdk "$JAVA_HOME" --android-sdk "$ANDROID_HOME"
```

It checks late SDK imports, generation, incremental invalidation, Legacy
fallback, Android/non-Android multi-targeting, design-time compilation,
strict multithreaded package tasks, consumer R8 rules and unchanged installed
workload files. The fresh handoff passed **15 stages** without optional runtime,
second-version upgrade or device checks.
The wrapper selects a content-addressed cache and verifies restored compiler
bytes, so repacking locally under the workbench version cannot accidentally
test an older cached package.

## Advanced host tools and Android work

For example, read the parser's usage without guessing a conventional output
directory:

```sh
python3 eng/workbench.py tool class-parse -- --help
```

`tool` accepts `generator`, `class-parse`, `grouped-bindings`, and
`binding-compatibility`. It preserves the tool's exit status, including tools
that report usage with a nonzero exit code.

With your own resolved reference directory and compiled consumers, the
compatibility CLI can extract and select contracts without a product SDK:

```sh
python3 eng/workbench.py tool binding-compatibility extract \
  .artifacts/full-profile.json /path/to/references /path/to/Microsoft.Maui.dll
python3 eng/workbench.py tool binding-compatibility select \
  .artifacts/full-profile.json .artifacts/selected-profile.json \
  /path/to/references /path/to/Frozen.Consumer.dll
```

The complete MAUI/corpus/runtime/device drivers additionally depend on the
original prepared Android build. They are **not** advertised as fresh-bootstrap
commands. See [portability and advanced paths](../docs/portability.md) before
using those preserved entrypoints. In particular, do not install global
workloads or choose an arbitrary ADB device to make a fixture pass.
